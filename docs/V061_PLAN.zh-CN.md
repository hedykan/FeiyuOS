## 一、界面动画与分条渲染

**问题**：设置页、主界面每次按键都清屏重画，光标移动会闪；页面切换没有过渡。

**硬约束**：整屏 8 位缓冲要 32 KB，设备跑久后最大连续块只有约 31.7 KB（2026-11-07 E2E 实测），不能依赖整屏缓冲。

**底层方案（建议）：分条渲染**
- 从 arena 借一条 240×16 的 8 位条带（约 3.8 KB），所有重绘按区域在内存里画好再推屏。
- 页面绘制函数支持「在指定区域、按偏移画」，滑动动画 = 每帧按不同偏移推各条，不需要整屏缓冲。
- 借不到内存就不做动画，直接切换（与现在一致）。
- 设置页整页闪烁随这套机制一起解决（光标移动只重画两行）。

## 二、顶栏信息与信息页

- 数据来源：时间（NTP）；天气 / 温度（`place://weather`，缓存 30 分钟，需联网和高德 Key；**设备没有环境温度传感器**，芯片温度不是室温）；位置（GPS 需 Cap，逆地理编码需联网，缓存）；电量、Wi-Fi、LoRa 消息、下一个提醒、运行中的程序、剩余内存（本地）。
- 顶栏右侧约 150 像素，最多 2～3 项。方案 A 固定槽位；方案 B 一个轮播槽位（时间 → 天气 → 位置）+ Wi-Fi 常驻（倾向 B）。
- 信息页：一整页信息卡片，内容可配置；第三个标签页（Agent | SSH | 信息）或 Fn+I；复用 0.6 的面板（ui panel）定时刷新。

## 三、settings 扩展包

- Fn+W 设置页保持内置（离线、配置损坏时的兜底入口）。
- 新增 `settings://`：`read settings://` 返回设置页所有行（与菜单同一个函数）；`settings://font`；`settings://key/<provider>` 走设备掩码输入，Key 不经过大模型；`settings://webtoken/regenerate`、`settings://portal` 每次确认；`settings://statusbar`、`settings://infopage` 配置顶栏和信息页；`settings://animation`。
- WiFi / LoRa / SSH / 对话记忆不接管，指向已有的 `wifi://`、`lora://`、`device://local/context/length`。
- 对话记忆长度的保存收进 `settings_store::set_context_kb()`，设置页和 `local` 包共用。

## 四、画布表达式与状态（实时渲染程序）

- 现状：`prog://` 无算术、无状态、`repeat` ≤ 10、以秒为单位；画布只有 `{t}` 线性变化和秒级 `source`。写不出「每帧读陀螺仪 → 算位置 → 重画」。
- 用户决定：**不加 ball 这类特殊指令**，做通用能力。
- 方案：画布增加 `vars`（状态）和 `update`（每帧赋值，只支持 `+ - * /`、比较、`min/max/abs`），参数里用 `"{x}"`；新增每帧读取的传感器绑定 `imu.ax / imu.ay`。
- 待定：表达式语法、变量个数上限、每帧赋值条数上限。
