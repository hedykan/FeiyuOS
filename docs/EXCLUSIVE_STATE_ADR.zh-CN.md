# 决策记录：两态模型与独占态

> **状态：已定，待实现**（0.8）。实现前还要上机量内存预算、试强制结束的按住时长和触发排队。
> 来源：2026-11-11 讨论；`feiyu-code.md` 的「程序运行时独占设备」是它的前身。

## 背景

- 设备没有 PSRAM，内部 RAM 约 320 KB（见 [固件开发约束](FIRMWARE_RULES.zh-CN.md)）。系统界面、网页服务、TLS、Lua 虚拟机同时在时，留给一个程序的连续内存很少。
- 现在程序的限制：单次最长 150 秒、休眠最长 60 秒、嵌套 3 层、后台 2000 万条指令、源码 16 KB、输出 2 KB。这些限制让短任务安全，但做不了长时间运行、持续采样和整屏图形。
- 屏幕和 TF 卡各占一条 SPI 总线，屏幕只由 UI 任务绘制。程序要直接画屏，就不能和系统界面同时画。

## 决定

设备只有两个运行态，不设第三个。

| | OS 态 | 独占态 |
|:--|:--|:--|
| 进入 | 开机默认；独占态退出后回到这里 | 运行一个声明了独占的程序 |
| 屏幕、键盘 | 系统界面 | 全部归程序 |
| Agent、触发、网页服务 | 运行 | 暂停（触发排队，见待定 3） |
| 程序时长 | 单次 150 秒 | 程序自己声明的上限 |
| 内存 | 与系统共用 | 系统让出界面与后台服务占的部分 |

监督层在两态之下，只做三件事：强制结束程序的按键、低电量保护、看门狗。程序拦不住它，它也不含业务逻辑。

### 切换

- 进入：记下 OS 态现场（当前页面、触发的下次时间）→ 停界面与后台服务、释放它们的内存 → 启动程序。
- 退出只有一条路径，五种原因都走它：程序返回、程序主动退出、用户强制结束、超时、低电量。释放程序 → 恢复现场 → 处理排队的触发 → 把退出原因和输出记进三条输入输出流（见 [0.7.2 计划 · D](V072_PLAN.zh-CN.md)）。

### 约束

1. 新功能先说明属于哪个态。系统页面、设置、调试属于 OS 态；长任务、持续采样、整屏图形属于独占态。
2. 扩展包声明自己在哪个态可用（OS / 独占 / 都可）。
3. 独占态的程序用的仍是同一套扩展包和 `gfx`，没有另一套接口。
4. Agent 不在独占态里运行；它在 OS 态写、测、改程序，再把设备交给程序。

## 已定（2026-11-12）

| # | 问题 | 决定 |
|:--|:--|:--|
| 1 | 强制结束 | **Fn+Esc**。程序收不到这个组合；按住多久上机试。 |
| 2 | 内存预算 | **上机实测后定**：停掉界面、网页服务、Agent 之后能拿到多大的连续块（不是空闲总量：用过一阵的堆是碎的，空闲 85–110 KB 时最大连续块只有 31 KB）。目标是虚拟机明显大于 OS 态的 48 KB，画布另算。 |
| 3 | 独占期间的触发 | **排队**：退出后再跑。上机测排队的上限和顺序（同一个触发在独占期间到期多次时怎么算）。 |
| 4 | Wi-Fi | 程序声明了联网相关的扩展包（`@uses` 里有 http、web、wifi 等），就**直接复用**现有的连接和扩展包，不另开一套网络接口；没声明的，进入独占态时可以释放 TLS 预留的大块内存。TLS 和 SSH 的大块内存不能同时存在，这条在独占态里照样成立。 |
| 5 | 程序怎么声明 | 程序头 `-- @mode exclusive` 和 `-- @timeout 秒数`，保存时检查；没声明的照常在 OS 态运行。 |
| 6 | 确认框 | 独占态里**不弹框**：程序声明的权限在进入独占态之前一次性确认（和现在保存时确认 `@uses` 一样）。运行中遇到没声明的需要确认的操作，直接失败。 |
| 7 | 实验台 | 时间可注入：`vat.millis`、`vat.sleep` 在实验台里快进；判定除了输出，加「跑 N 帧后的画面」与期望比对。 |
| 8 | Agent 的长对话 | **不进独占态**。Agent 是 OS 态的用户界面；长对话的问题（对话存卡、流式收发、内存）在 OS 态里解决。 |

## 还要上机确认的

- 第 1 条的按住时长；第 2 条的实测数字；第 3 条的排队行为。
- 程序之间不共用数据（每次调用都是新的虚拟机）：如果「程序共用数据」还没做，独占态的程序只能是单个文件。

## 不做

- 不做多个程序同时运行。
- 不做第三个态（例如「半独占」「后台常驻」）。有这种需求时先看能不能用触发 + 短任务表达。
