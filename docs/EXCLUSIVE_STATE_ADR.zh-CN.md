# 决策记录：两态模型与独占态

> **状态：草案**。0.7.2 不实现独占态；这份文档先把边界定下来，实现前逐条把「待定」填完。
> 来源：2026-11-11 讨论；`feiyu-code.md` 的「程序运行时独占设备」是它的前身。

## 背景

- 设备没有 PSRAM，内部 RAM 约 320 KB（见 [固件开发约束](FIRMWARE_RULES.zh-CN.md)）。系统界面、网页服务、TLS、Lua 虚拟机同时在时，留给一个程序的连续内存很少。
- 现在程序的限制：单次最长 150 秒、休眠最长 60 秒、嵌套 3 层、后台 2000 万条指令、源码 16 KB、输出 2 KB。这些限制让短任务安全，但做不了长时间运行、持续采样和整屏图形。
- 屏幕和 TF 卡各占一条 SPI 总线，屏幕只由 UI 任务绘制。程序要直接画屏，就不能和系统界面同时画。

## 决定

设备只有两个运行态，不设第三个。

| | OS 态 | 独占态 |
|:--|:--|:--|
| 进入 | 开机默认；独占态退出后回到这里 | 运行一个声明了独占的程序 |
| 屏幕、键盘 | 系统界面 | 全部归程序 |
| Agent、触发、网页服务 | 运行 | 暂停（触发排队，见待定 3） |
| 程序时长 | 单次 150 秒 | 程序自己声明的上限 |
| 内存 | 与系统共用 | 系统让出界面与后台服务占的部分 |

监督层在两态之下，只做三件事：强制结束程序的按键、低电量保护、看门狗。程序拦不住它，它也不含业务逻辑。

### 切换

- 进入：记下 OS 态现场（当前页面、触发的下次时间）→ 停界面与后台服务、释放它们的内存 → 启动程序。
- 退出只有一条路径，五种原因都走它：程序返回、程序主动退出、用户强制结束、超时、低电量。释放程序 → 恢复现场 → 处理排队的触发 → 把退出原因和输出记进三条输入输出流（见 [0.7.2 计划 · D](V072_PLAN.zh-CN.md)）。

### 约束

1. 新功能先说明属于哪个态。系统页面、设置、调试属于 OS 态；长任务、持续采样、整屏图形属于独占态。
2. 扩展包声明自己在哪个态可用（OS / 独占 / 都可）。
3. 独占态的程序用的仍是同一套扩展包和 `gfx`，没有另一套接口。
4. Agent 不在独占态里运行；它在 OS 态写、测、改程序，再把设备交给程序。

## 待定

| # | 问题 | 备注 |
|:--|:--|:--|
| 1 | 强制结束用哪个键、按多久 | 现在控制台用 `` ` `` 中断、Esc 取消；独占态里程序可能要用 Esc，需要一个程序收不到的组合 |
| 2 | 内存预算 | `feiyu-code.md` 的估计：Lua 虚拟机 24–48 KB，画布 4 位色 16 KB / 8 位色 32 KB；要实测让出界面和网页服务后能有多大的连续块 |
| 3 | 独占期间的触发 | 排队、丢弃还是合并成一次；排队要有上限 |
| 4 | Wi-Fi | 程序要联网时保留，否则关掉省电省内存；TLS 预留块怎么处理 |
| 5 | 程序怎么声明独占 | 程序头的声明项名字、超时的写法；保存时检查 |
| 6 | 独占态里要不要确认框 | 需要确认的操作（红外、蓝牙写入等）在程序运行前一次性确认，还是运行中弹出 |
| 7 | 实验台怎么测 | 独占态程序在实验台里的模拟方式；长时间运行怎么压缩成可重复的测试 |
| 8 | Agent 的长对话 | 对话存卡、流式收发、每轮喂看门狗；是算 OS 态里的长任务，还是另一种独占 |

## 不做

- 不做多个程序同时运行。
- 不做第三个态（例如「半独占」「后台常驻」）。有这种需求时先看能不能用触发 + 短任务表达。
