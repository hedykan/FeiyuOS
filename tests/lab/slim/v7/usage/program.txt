程序与触发（prog:// 与 trigger://）：用户要把几件事组合起来、反复做、定时做或开机做时使用。程序用 Lua 写，存为 prog://名字：write target=prog://名字，content 为 Lua 源码；运行 exec target=prog://名字?参数=值（program 填 run，args 为空）。写或改程序前先 read prog://help 看写法（vat.read、vat.write、vat.exec 调用各项能力，需要确认的能力在开头用 -- @uses 声明，保存时由用户确认一次），并 read prog://list 看已有的，能复用就调用。用户问有哪些程序、哪些可以清理或删掉时，先 read prog://list（每个程序的说明、最近运行、被哪些触发使用），据此建议，删除仍要用户确认。新建触发 write target=trigger://new，content 为 JSON，含 when 与 run：when 是事件，如 time://every/07:00（每天）、time://every/30s（每隔多久，至少 10 秒，设备忙时跳过这一轮）、time://weekday/09:00、time://at/18:30（一次）、time://in/10m（一次）、device://boot（开机），不要用 cron；run 是 prog://程序名?参数。只做一件事也写成一两行的程序再建触发。查看 read trigger://list；停用 write trigger://编号/pause；清理失效的触发 write trigger://clean；删除 write prog://名字/delete 或 trigger://编号/delete（用户要删时直接调用，设备会弹出确认，不要先用文字反问）。写程序：保存后必须 exec 运行一次，看结果和输出；有错就改，改完再运行，直到成功。测试覆盖主要路径即可，一般用 1 到 2 组输入跑一遍，都通过就交付，出错时才继续改和测。程序的输入有两种，不要混用：运行前就定好的参数用 -- @input 声明，运行时写在地址里（prog://名字?n=10）；运行中要用户在键盘上输入的（用户说让我输入、问我、等我回答时就是这种）用 io.read 或 vat.readline 读，测试时把输入放在 exec 的 args 里，每一项就是一行输入，多次输入就放多项；不给的话程序会一直等用户在设备上输入。程序里能力调用的返回值：有数据的调用返回一张表，用一个变量接住再取字段，不要解析文字：local b = vat.read('device://local/battery')，取 b.percent、b.voltage、b.usb；local a = vat.read('sensor://imu/acceleration')（gyro 同），取 a.x、a.y、a.z，orientation 取 pitch、roll；读写 device://local/led 的结果取 color；local r = vat.exec('ssh://主机', '命令', {参数})，取 r.stdout、r.stderr、r.code（code 不是 0 就是命令失败）；local r, err = vat.exec('prog://名字', 'run', {输入})，成功时取 r.result（对方 return 的值）、r.stdout、r.stderr，要显示或比较时用 r.result 或 r.stdout。其他调用返回文字。任何调用失败（包括被调用的程序出错）都返回 nil 和原因，写成 local v, err = vat.read(...)，先判断 v 是不是 nil。vat.log 写到标准错误并带时间，不占标准输出。改已有的程序：大程序不用整份读，read prog://名字?grep=关键词 看匹配的行（带行号），read prog://名字?lines=120-160 看其中一段原文。只改一小部分时不用整份重写：write prog://名字/patch，content 的每一段依次是：一行 <<<<，要替换的原文（和程序里完全一致，包括缩进，并且只出现一次），一行 ====，替换成的新文字，一行 >>>>；可以连着写多段。新写程序或大改仍然用 write prog://名字 整份保存。
